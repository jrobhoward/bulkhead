# Bulkhead: Security

2026-10-25, native apps 2026-11-01 · Companion to [ARCHITECTURE.md](ARCHITECTURE.md)

The threat model as built: what Bulkhead protects, whom it trusts, each boundary between trusted and untrusted parts with the controls on it and the gaps found, and the fuzz targets. Findings are numbered S1 and on; each is fixed, and a new one would be a ROADMAP item. First drafted in the 2026-10-10 review and kept current as Phases 2, 3 and 5 added boundaries.

## Reporting a vulnerability

Report it privately through the repository's Security tab ("Report a vulnerability"), not in a public issue. Bulkhead is a research project without support (README.md): reports are read, but there is no response time and no fixed releases.

## What is protected

- **Singleton exclusivity.** A singleton drives devices; two copies running at once is the worst outcome (DESIGN.md, "Distribution"; `docs/tla/VERIFICATION.md`).
- **App isolation.** Each app sees only the capabilities its manifest declares and the operator grants: its own buckets and files, shared buckets it was granted, the secrets it lists.
- **Secrets** bound on the node, and the node's keys: the cluster key and the operator's trusted signer keys.
- **Availability** of the node and of other apps when one app misbehaves.
- **Logs and the audit log**, which operators and the soak's checker read as the node's own record.

## Whom Bulkhead trusts

| Party | Trusted to | Not trusted to |
| --- | --- | --- |
| The operator (anyone who can open the admin socket: the node's user, mode 0600; or holds a key the `[admin]` operators file lists) | everything: deploy, kill, confirm failover, read state | — |
| A signer in `trusted_keys` | publish code the node may run | do anything its grant does not allow; `bulkhead-runner`'s restrictions and the grant are the boundary even for signed code |
| An app | use what it was granted | reach other apps' data, the host, or other apps' messages beyond what routing allows |
| An unconfined app (ROADMAP AP4: its manifest's `unconfined`, granted by policy by name, allowed by node config and listed in the helper's configuration) | what the operator's own code may do as its user: open its own sockets on the host's network, read whatever its user may read in its root (the host's `/etc` among it), make any system call the helper's inherited list allows; and use what it was granted of the node's services | reach other apps' or the node's files (its root shows only its own directories, and Unix permissions hold), other apps' messages beyond routing, or past its cgroup or jail |
| The node, under the privileged helper | start, signal and end the instances it runs, as any app's user | run anything but `bulkhead-runner`, as root, the node's user or a user outside the helper's range; give one app's user to another; put an instance outside its fences; reach any directory outside the helper's binds |
| A cluster member (a node whose key is in the peers file) | what its own instances could do on the node: call, cast, link and send exit signals within the messaging ACLs, as its stamp on each frame says; call an app by name from its host, as a standby's ingress does to forward an HTTP request (not subject to messaging ACLs, as host calls are not); take part in failover | speak for another node's instances (a frame whose sender pid is on another node is dropped); its stamps are trusted, so a member that lies about its senders' apps passes ACLs it should not |
| The witness | arbitrate its pair | — |
| The HTTP ingress driver (`bulkhead-ingress`, ROADMAP DA2) | accept on the `[http]` listeners, read its certificates and keys, call the apps that own routes with any request, ask where such an app runs on the failover partner and have the node call it there | reach anything else of the node's: other apps, buckets, secrets, the cluster key; its process is fenced as any native instance's |
| The remote admin driver (`bulkhead-admin`, ROADMAP DA7) | terminate operators' TLS with the admin key, refuse keys the operators file does not list, carry connections to the node | act for an operator: the node checks each request's signature itself; it can watch, delay or drop requests and answer an operator falsely |
| The metrics driver (`bulkhead-metrics`, DA7) | serve `GET /metrics` with the node's text | anything else: it holds no file, key or call |
| The resolver driver (`bulkhead-resolve`, ROADMAP DA9) | answer the node's lookups, open TCP to its nameservers | reach anything else: other apps, other addresses, buckets, secrets; the addresses it answers are checked against the asking app's rules |
| A datasource's driver (`bulkhead-sql-<name>`, ROADMAP DA3) | read its datasource's password and CA files, have the node connect it to that database's one address, run the statements the node forwards and answer them | reach another database, another address, an app, a bucket or another secret; choose which app a statement is for, or exceed an app's connection cap: the node keeps the grants, the caps and the transactions |
| An app's egress driver (`bulkhead-egress-<app>`, ROADMAP DA4) | send the requests the node forwards for its app, have the node connect it to the hosts and ports its app may reach, verify servers against the roots the node gave it | reach another app's destinations, requests or keys, another address, a bucket or a secret; choose which requests go out: the node keeps the grant, `allow`, `methods`, the headers check and the cap |
| HTTP clients, listener clients, Modbus masters | nothing | anything beyond the routes, handlers and tables they reach |
| The Modbus drivers (`bulkhead-modbus`, `bulkhead-modbus-primary`, `bulkhead-modbus-server`, ROADMAP DA5) | poll the configured devices over connections the node opens to their addresses alone, serve masters on the port the node bound, cast updates to the `deliver_to` apps, answer the calls the node forwards | reach another address, another app, a bucket or a secret; decide which app may read or write a device or set the served tables: the node checks each call |
| Modbus devices polled | return register values | crash or stall their driver |

Cluster members trust one another fully, as nodes of an Erlang cluster do: mutual TLS with pinned keys decides who is a member, and a member is not checked further. A member compromised is a cluster compromised.

## Boundaries

### App and host

- **Controls.** the restricted process ("Native-process apps" below); `memory_max` and instance limits; the callback deadline, then a kill; mailboxes bounded in messages and bytes (`mailbox_max`, `mailbox_max_bytes`) and `message_max_bytes`; host-object limits (timers, monitors, links, pending calls, groups, watches); an `access-denied` answer to any request outside the grant; a misbehaviour policy (ROADMAP PS5) that kills an instance past `refusals_max` refusals (`access-denied` and messaging-ACL refusals) within a period or, if set, past `requests_per_sec`, and quarantines an app such kills and protocol breaks hit `quarantine_after` times within a period, until an operator starts it again. Exit signals into an instance are bounded by the node's instance count, timers and watch notices by their own limits.
- **Gaps.** None found; S2, S3, S6 and S11 are fixed. A writable directory volume is bounded only by the filesystem quota the operator gives it; a ZFS volume (ROADMAP ZV1) by its quota, which ZFS enforces (`refquota`).

### App and app

- **Controls.** Buckets namespaced by app; shared buckets by grant, read-only or read-write; secrets by name and grant; groups by manifest scope; SQL datasources by name and grant, with a connection cap per app; registered names limited to those the manifest lists; messaging ACLs (`messaging_acl.accept_from`, `may_call`, by app name) on calls, casts, exit signals and links, checked on the target's node against the host-stamped sender.
- **Gaps.** S1 is fixed. Without a `messaging_acl`, an app may call, cast, link or send exit signals to any pid it learns, as before; the lists are opt-in. Monitors are not checked (they only observe).

### The admin socket and the remote admin API

- **Controls.** A Unix socket created owner-only; bundles verified against `trusted_keys` whoever uploads them; uploads capped at 512 MiB; changes recorded in `audit.log`. The remote admin API (`[admin]`) is TLS 1.3 with raw public keys both ways, terminated since ROADMAP DA7 by the admin driver `bulkhead-admin`, not the node: it presents the admin key (a key of its own, never the cluster key), which the operator pins (`--node-key`), accepts only a key the operators file lists, gives a handshake 10 s, and copies the connection's bytes to a stream into the node's admin API. Each request must carry the operator's signature (`Bulkhead-Auth`, Ed25519 over the method, path and query, the body's SHA-256, the node's admin key, the time and a nonce), which the node checks against its own reading of the operators file before acting: the time within 60 s of its clock, the nonce not seen in the last 120 s (100,000 remembered at most), the body as sent. A refused request is answered 401 and recorded in `audit.log` (`remote_admin_refused`); every accepted request but a `GET` is recorded with the operator the signature proves. The driver runs as any native instance does (Landlock and seccomp, or Capsicum; under the helper a user of its own), with the listener, its two files read-only and the right to open admin streams, nothing else; its messages come from itself alone. Tested on Linux and FreeBSD 15, under the helper as root on both (`tests/remote_admin.rs`, `bulkhead-host/tests/priv.rs`, the e2e scripts).
- **Gaps.** Every listed operator has every right the socket gives: there are no read-only operators. Responses are not signed: the admin driver, compromised, can show an operator a false answer (a wrong `status`, a doctored `logs`), though it cannot act (decided with the user 2026-11-14 to leave this documented). A compromised driver also sees every request and answer in clear, holds the admin key (and so can impersonate the node to operators who pin it), and can delay or drop requests; it can replay none, as each nonce is spent once and a stale time refused. Operators' clocks must be within 60 s of the node's. The node's HTTP parser for the admin API (hyper) reads whatever the driver sends on an admin stream, unsigned bytes included, before the signature is checked. Anyone who can reach the address can open connections and start handshakes; the driver holds 64 connections at once, so put the address on a management network. Removing an operator stops new connections, not one already open, including a stream (`bulkhead events`, `logs --follow`) that has run since. The shell keeps its history, call bodies included, in the operator's `~/.config/bulkhead/history`.

### Node and node

- **Controls.** QUIC with TLS 1.3 and raw public keys pinned per node id; a hello naming the node id, checked against its key; frames of at most 64 MiB; a versioned CBOR wire format; sessions that discard frames from an ended session or an earlier start.
- **Gaps.** None beyond the trust above; S5 and S8 are fixed. Calls from one peer in progress at once are capped (`[cluster] incoming_calls_max`). Credit for waited casts lets a peer's instances hold room in a local mailbox (`[cluster] cast_credit` casts and `cast_credit_bytes` per sender and target); all the credit in one mailbox holds at most half of its messages and bytes, and room a local sender waits for is never granted.

### Ingress clients

- **Trace context** (ROADMAP O1). A client's `traceparent` header is read by the ingress driver as two hexadecimal ids and a flag; it decides only which trace id the request's records carry and whether the request is traced, never routing or access. A client that marks its requests sampled makes each travel to its app as a CBOR frame rather than a hot one (about 2.5 times a call's cost on the Raspberry Pi 5, BASELINE.md, 2026-11-22), and its records carry ids it chose: `[tracing] accept_traceparent = false` ignores clients' headers. A traced request an app sends out carries `traceparent` to the server unless `[egress] traceparent = false`.
- **HTTP.** Parsed by the ingress driver, not the node (below). Routes by host and path prefix; body limit per route (1 MiB default); header timeout 10 s, body timeout 30 s; at most 1,024 connections per address; reply size limit; TLS with rustls on ring, certificates reloaded on change. No client certificates yet.
- **Listeners.** `max_connections` and an idle timeout per listener. An app's connections are passed to its instances, many to each, so a client's bytes reach the app's code unparsed by the node; the node keeps a copy of each socket and shuts it down when the listener stops or the connection idles (`TCP_INFO`), whatever the app does with its copy.
- **Gaps.** None found.

### The ingress driver

Since ROADMAP DA2 (2026-11-14) HTTP and TLS from clients are parsed in `bulkhead-ingress`, a native instance the node starts for `[http]` (DESIGN.md, "HTTP ingress"), so a bug in hyper, rustls or the driver's own code is a compromise of that process, not of the node.

- **Controls.** The runner's fence, as for any native instance: Landlock and the seccomp allow-list on Linux, Capsicum on FreeBSD, and under the privileged helper a user of its own (with a cgroup and namespaces, or a jail). Its profile is the node's, not a manifest's: `accept4` on the listening sockets the node passed and nowhere else, read rules on its certificate and key files alone, and calls only to the apps that own routes, following the route table (their `accept_from` passes, since declaring routes accepts HTTP requests; `may_call` is the node's list). It answers the node's reload call and the `routes` host event; its frames are read and checked as any app's. `Request::Elsewhere` and a `CallApp` with `partner` are answered for a driver whose profile forwards, and only for apps it may call. `memory_max` 512 MiB, one instance; it restarts after a crash with at most 1 s of backoff and its supervisor never gives up, so a crash costs the ingress at most about a second, and the node keeps the sockets (clients connecting meanwhile wait in the backlog). Its six counters reach the node's metrics as an app's do. Tested on Linux and FreeBSD 15, with the helper as root on both (`bulkhead-ingress/tests`, `tests/drivers.rs`, `tests/priv.rs`); its reading of an app's reply is fuzzed (`http_reply`).
- **Gaps.** A compromised driver holds the ingress's TLS keys and every client's traffic in clear, and can send the routes' apps any request: apps see no client address, and headers such as `x-forwarded-for` are the client's or the driver's to write, so an app that trusts them trusts the driver. Without the helper it runs as the node's user, fenced by Landlock or Capsicum alone. A client that can crash it (filling its 512 MiB with bodies across `max_connections`, at 1 MiB each by default, or a bug) can keep it restarting, the ingress down for up to a second each time and connections in flight dropped. A certificate or key replaced by a rename (certbot's renewals, which switch a link) restarts the driver, since its read rule (Landlock) or descriptor (FreeBSD) is bound to the file it was given at start: the node checks each file's identity (ROADMAP DA2b), and the connections in flight are dropped. Client certificates (`client_ca`) are verified in the driver, so an app's trust in `client_cert` is trust in the driver as well; the app gets the leaf's fingerprint and DER, and the driver parses no more of it than rustls's WebPKI verification does. One connection's request costs more CPU than the node's own ingress did (1.5 to 1.6 times on the Pi, BASELINE.md 2026-11-14), so a flood of requests costs the machine more for the same clients.

### The resolver driver

Since ROADMAP DA9 (2026-11-14) host names are resolved in `bulkhead-resolve`, a native instance every member node starts (DESIGN.md, "Host names"), so a DNS reply is parsed by hickory-resolver in that process, never by libc in the node.

- **Controls.** The runner's fence, as for any native instance, and under the privileged helper a user of its own. Its manifest is the node's: TCP to each nameserver's address and port and nothing else (the node opens each stream, checking the rule); no listening, binding or files; messages from its own instance alone, sent and received (`messaging_acl`), so no app can cast it a forged answer; 64 MiB, one instance. It may not look names up itself. Its configuration is text the node read (`resolv.conf`, the hosts file), not files it opens. An answer is a list of addresses, which the node reads (`bulkhead_host::Names`) and checks against the asking app's `connect` rules, `[egress] allow` and the egress address guard, as before. The node resolves no name without it: `scripts/check.sh` fails on a call to libc's resolver in the node's source and on a DNS library in its tree. Tested on Linux and FreeBSD 15, under the helper as root on both (`bulkhead-resolve/tests`, `tests/names.rs`, `tests/priv.rs`).
- **Gaps.** A compromised resolver answers any address for any name, as a compromised nameserver could, inside each asker's rules; it learns every name the node's apps look up. It may send what it likes to its nameservers on its streams. A crash costs lookups a second at most (they are asked again). hickory's DNS parser is Rust; Bulkhead does not fuzz it. A UDP socket is never passed, so a nameserver without DNS over TCP answers nothing. DNSSEC is not validated, as libc did not.

### HTTP egress

Since ROADMAP DA4 (2026-11-15) each app granted `bulkhead:http-egress` has a driver of its own, `bulkhead-egress` running as the app `bulkhead-egress-<app>` (DESIGN.md, "HTTP egress"), so a server's response and TLS handshake are parsed by hyper and rustls in that process, and the node parses neither.

- **The node keeps the decisions.** An app reaches only the schemes, hosts and ports its manifest's `allow` lists, inside node config's `[egress] allow`, with the methods it lists, once policy grants `bulkhead:http-egress`; anything else is refused in the node before the driver hears of it. Forbidden request headers (`connection`, `keep-alive`, `proxy-*`, `transfer-encoding`, `upgrade`, `host` set from the URL) are refused there too. Requests in flight are capped per app (the node holds the permit until the driver answers), and timeouts bound the wait for headers and between body chunks, the node's own wait bounded above them. Redirects are not followed.
- **The node opens each connection** (`Request::ConnectTo`): only for a host and port inside the `allow` entries of the driver's app's running instances, a name resolved by the resolver driver, and a name that resolves to loopback or link-local addresses (cloud metadata at 169.254.169.254) refused at each connection unless `allow_loopback`, or into `[egress] deny`, the private ranges by default (ROADMAP DA4b), so a name an app may reach cannot be pointed at the internal network; an address is reached only when an entry names it. Through `[egress] proxy` the node sends the `CONNECT` itself, for the allowed destination alone, so a driver cannot ask the proxy for anything else; the proxy resolves the name then, and its own rules stand in for `deny`. The driver opens no socket, so a compromised one reaches nothing its app may not.
- **TLS** verifies the server against the system's roots and node config's CA file, which the node reads (again on `reload-tls`) and passes to the driver as PEM. An app's client certificate and key (`[egress.identities.<app>]`) are bound read-only into its driver's root, never passed as text; a compromised driver holds its own app's key and no other's.
- **The driver's fence.** The runner's fence, as for any native instance, and under the helper a user of its own (a cgroup and namespaces, or a jail). Its profile is the node's, by its name: no connect rules, listening, binding or files; messages from its own instance alone (`messaging_acl`), so no app can call it; 256 MiB, one instance, a supervisor that never gives up. A response body is at most `[egress] max_response_body` (16 MiB at most, a frame's limit).
- **Tested** on Linux and FreeBSD 15, under the helper as root on both (`bulkhead-egress/tests`, `bulkhead-host/tests/egress.rs`, `drivers.rs`, `priv.rs`, and `scripts/priv-e2e-systemd.sh`, where strace shows the node making each connection and the driver none).
- **Gaps.** Private ranges (10/8, 172.16/12, 192.168/16, fc00::/7) are allowed for any name an entry allows, since internal services live there; a `*.internal` entry trusts whoever answers DNS for that zone. A compromised driver holds its app's requests, with the keys in their headers, and every response in clear, and can answer the app falsely; it can send what it likes to its app's servers over connections the node opened, as the app could. A server that can crash the driver (a bug in hyper or rustls) costs that app's requests in flight and a second of restarts, not the node or another app. No outbound proxy (HTTP `CONNECT`) and no client certificates (DA4b).

### Blobs

Since ROADMAP BL1 (2026-11-15) apps pass data to each other as blobs: sealed memory the node makes (DESIGN.md, "Blobs").

- **Controls.** Only an app granted `bulkhead:blobs` makes, shares, opens or releases one; making one counts against its `max_bytes`, inside the node's ceiling and its largest blob. Only the instance that made a blob seals it, and the node seals it against writes only once no writable mapping remains, so neither the writer nor a reader can change a sealed blob: writes, resizing, writable mappings and `mprotect` are refused (by the seals, and on FreeBSD also by the descriptors' rights: the writer's read, write, seek, map and stat; a reader's read, map read-only and stat). Only the writing app shares it, and only with an app its messaging ACLs let it call; only that app and the writer's open it. The id grants nothing. The node does not read the bytes. Tested on Linux and FreeBSD 15, under the helper as root on both, the writer and the reader under users of their own (`bulkhead-host/tests/blobs.rs`, `priv.rs`).
- **Gaps.** A descriptor an app opened cannot be revoked: a blob stays readable to it after it is freed, until it closes it, and an app that keeps one keeps its memory. On FreeBSD a mapped blob counts in every holder's memory, so a writer can make a reader that maps its blobs use memory; the reader chooses whether to map. An app shared a blob learns its contents, and the writer learns nothing of who read it.

### App sockets

- **Controls.** Once policy grants `bulkhead:sockets`, an app's sockets reach only the blocks and ports its manifest's `connect` rules list, bind only what its `bind` rules list, and listen only with `listen`, all inside node config's `[sockets]`; the node checks every address as it is used (bind, listen, accept, connect, each UDP send and receive) and passes an app only connected TCP streams, so a socket cannot move outside the rules after it opens. Loopback, link-local (cloud metadata at 169.254.169.254) and unspecified destinations are reached only through a rule inside that range, so a broad rule such as `0.0.0.0/0` does not reach the node itself. Name lookups are allowed only with `connect` rules, and their answers are checked like any address. Sockets open at once are capped per app (`max_sockets`).
- **Gaps.** Private ranges are reached by any rule that covers them. A rule names addresses, not hosts, so an app allowed a block reaches every service in it; the resolver driver, or whoever answers its nameservers, can steer a name to any address inside the rules. The protocol on the socket is the app's own, parsed in its process: TLS, if any, runs in the app with its keys in its memory. Bytes in flight are bounded only by the app's memory and the kernel's socket buffers; there is no rate limit. A listening app's accepted connections count against `max_sockets`, which bounds them; there is no per-address limit.

### Native-process apps

An OS process restricted by `bulkhead-runner` confines an app's code, and the grant is enforced on the node, in the code that answers each request:

| | Native app |
| --- | --- |
| Memory | Its own address space; `memory_max` as a cgroup's `memory.max` or `RLIMIT_DATA` (FreeBSD: `RLIMIT_AS`) |
| What the code can call | The system calls on the seccomp allow-list (`bulkhead_runner::seccomp`); any other ends the process. Landlock fences files |
| CPU | The callback deadline in wall time, then a kill; threads may run between callbacks. CPU itself is not limited: per-instance limits (PS6) were removed on 2026-11-19 for the `cpu` controller's cost on every call (ROADMAP PS6b; CPU limits are parked) |
| Files and network | Read-only: system libraries, its own directory, its `priv/` files and read-only volumes; read-write: its read-write volumes, executing nothing from them; network: TCP streams the node connected or accepted on the grant's rules, or accepted on the app's listeners, and passed to it; listening sockets and UDP sockets stay in the node |
| Reaching other apps and the node | Frames on its channel, as its instance |

- **Controls.** A native app's program runs only through `bulkhead-runner`, which, before the program runs and while it has one thread: marks itself non-dumpable (no core dump, no ptrace from the node's user); restricts itself with Landlock to reading the system library directories, the program's own directory, the app's `priv/` files and its read-only volumes, reading and writing its read-write volumes (files, directories and symbolic links, and renames within one; no devices, sockets or pipes, no device ioctls), executing only the program (and its ELF interpreter), writing nothing else and binding or connecting no TCP port; and installs the seccomp filters (below). A kernel without Landlock is refused unless `[native] landlock_optional`. Both stay in force across the exec of an executable and in anything it starts. Not being dumpable does not (`execve` resets it for a readable program), so `bulkhead_native::app::serve` sets it again before the app's code runs. The node runs the process with an empty environment, in its own process group, with the parent-death signal (`SIGKILL`) and no core dumps; with `[native] cgroup`, in a cgroup of its own with `memory.max` (no swap) and `pids.max`. A singleton's process is killed when the node's lease ends, idle or in a callback (`crashed: lease_ended`), so it cannot drive devices past the lease while it runs threads of its own. The process reaches Bulkhead only over its pipe, as its instance: messages carry that instance's pid and app, checked by messaging ACLs as for a component, and its requests are the process functions a component imports, with the same host-object limits. A manifest may declare only `bulkhead:logging`, `bulkhead:keyvalue`, `bulkhead:groups`, `bulkhead:config`, `bulkhead:secrets`, `bulkhead:metrics`, `bulkhead:http-routes` (requests arrive as calls, as for a component), `bulkhead:files` (volumes the operator's `[volumes]` names, passed only with the grant and fenced by Landlock as above) `bulkhead:sql` (datasources checked by the node and run by each one's driver, whose credentials never reach the app) `bulkhead:http-egress` (each request sent by the node's egress client on a component's rules, so the app holds no egress socket and no TLS) and `bulkhead:sockets` (the node makes every socket on the rules and the address guard, and counts `max_sockets`: a passed TCP stream is connected, and the node shuts it down when the app closes it, so a kept copy is dead; UDP stays in the node, which checks each datagram's destination and source, since Linux's `sendmsg` overrides a connected UDP socket's peer); each request is answered by the code a component's import runs, on the same checks (the grant, the manifest's buckets, groups and secret names, read-only shared buckets, quotas and limits).
- **System calls.** The runner's seccomp filters are an allow-list (PS4, 2026-11-11): memory, threads and processes inside the fence, signals to itself, clocks, descriptors, the file calls (Landlock decides which files), and reading and writing sockets the node passed. A call outside the list raises `SIGSYS`: an app on `bulkhead_native::app::serve` records the call and ends, and its instance exits `crashed: syscall <name>`; any other process dies of the signal (`crashed: syscall refused`). Not on the list, among others: `bind` and `listen`, `unshare`, `setns`, `mount`, `chroot`, `bpf`, `keyctl`, `perf_event_open`, `userfaultfd`, `memfd_create`, `execveat`, `seccomp`, the credential calls, kernel modules and System V IPC. Some listed calls are refused with `EPERM` and the app runs on: signals to any process but itself (`kill`, `tgkill`, `rt_sigqueueinfo`, `rt_tgsigqueueinfo` by pid; `tkill`, `pidfd_send_signal` and `pidfd_getfd` always; for an instance bound to a failover lease, the runner first forks a watchdog that kills the app at the lease's end without the node, with no filesystem access and signals only to itself and the app; `bulkhead_native::lease`), `ptrace`, `process_vm_readv` and `process_vm_writev`, new sockets (`socket`), `connect`, `accept` and `accept4` (a passed stream cannot be moved or accept connections), `io_uring` (whose operations bypass the filters: its socket operation makes a socket without `socket`, and Landlock does not fence UDP), `clone` with a flag that makes a namespace (a user namespace would give the app capabilities over what it makes), `socketpair` outside `AF_UNIX`, and `ioctl` beyond the descriptor requests and the terminal check. `clone3` answers `ENOSYS`, since a filter cannot read its flags, and libc falls back to `clone`. Checked on x86-64 (Linux 6.8, glibc 2.39) and aarch64 (Linux 7.0, glibc 2.43) with every test app and example; an app built against another libc, or one whose libraries make other calls, finds out as that exit. The HTTP ingress driver gets a narrower list (`--profile ingress`, ROADMAP DA2b, 2026-11-21): the apps' without starting or waiting for processes, any call that writes or changes a file or a directory, and copies between descriptors (`bulkhead_runner::seccomp::INGRESS_WITHOUT`; it keeps `AF_UNIX` socket pairs, which tokio's signal driver makes when the driver is built beside the node), so a bug in hyper or rustls that runs code there cannot start a program or change a file even where Landlock would let it; it keeps `execve`, which the runner's own exec of the driver needs once the filters are on. A `strace` of its tests (x86-64) found none of the calls it lacks, and its tests and the node's run under it on x86-64 and aarch64; its tests build the driver alone, without tokio's `signal` feature, so `scripts/priv-e2e-systemd.sh`, which runs the driver built with the node, is what found the socket pair it needs.
- **The channel.** The node reads and writes the rings through a mapping of a memfd the app also holds. The node trusts none of the positions the app writes there, copies each frame out before decoding it, and seals the memfd's size so the app cannot shrink the file under the mapping (S11). On FreeBSD `memfd_create` makes an anonymous shared memory object with the same seals, so the channel and published snapshots are sealed as on Linux.
- **Under the privileged helper** (`[priv]`, ROADMAP PS1, 2026-11-11) the runner and its fences run as above, inside the helper's: the app's own user, and on Linux its cgroup, namespaces and minimal root ("The privileged helper", below).
- **Unconfined apps** (ROADMAP AP4, 2026-11-21). An app whose manifest declares `unconfined` runs without the runner's fences: `bulkhead-runner --unconfined` sets neither Landlock nor its seccomp filters on Linux, and leaves capability mode off on FreeBSD (the app opens its preopens by path), so the app opens sockets of its own, reads what its user may in its root and makes any system call the helper's inherited list allows (on Linux the socket calls are on it; `bpf`, `unshare`, `setns`, `mount`, `open_by_handle_at` and the rest of what the helper refuses stay refused). It stays non-dumpable (FreeBSD: not traceable), and a singleton's lease watchdog is fenced as for any app. It runs only under the helper, as the app's own user, in its cgroup and PID, mount, IPC and UTS namespaces (Linux) or its jail and `rctl` rules (FreeBSD), with the host's network (no network namespace; the jail inherits the host's addresses) and the host's `/etc` read-only in its root (FreeBSD: `/usr` whole, too). Consent on four sides: the manifest (with a reason the operator sees), policy granting `bulkhead:unconfined` to the app by name (refused in `[defaults]` or a signer's entry, so signing a bundle never unconfines it), node config `[native] allow_unconfined` (refused without `[priv]`), and the helper's own configuration listing the app. The node checks the first three at every build of the bundle (deploy, upgrade, restore, start, a DR copy), so a consent withdrawn stops a stored app from starting; the runtime refuses to start one without the helper whatever the node decided; and the helper refuses an unconfined spawn of an app its configuration does not list, and the runner's `--unconfined` flag in any spawn not marked unconfined, so a compromised node cannot unconfine an app root did not name. Gaps: such an app's code is trusted as the operator's own. Its sockets reach whatever the host's network reaches (the node's loopback listeners, cloud metadata, private ranges), outside `[sockets]` and the address guard; its traffic is not seen by the node. It reads every file in its root its user may (`/etc` but `shadow` and the like, the system libraries, its own directories), and the kernel's whole interface the helper's list allows is reachable. Its messages, grants and node services are checked as any app's.
- **Sender channels** (ROADMAP AP1). An app's own threads ask the node through sender channels, each a channel like the instance's (a memfd sealed the same way, a door, a bell), made by the node on request and passed on the descriptor socket, up to `limits.senders_max` per instance. Their frames are the same frames, read and checked the same way, by a node task of their own; a sender acts as its instance (messaging ACLs, grants) and may ask for a subset of the requests (casts, calls, keyvalue but watches, metrics, another sender); anything else, or a broken frame, ends the instance. A sender may keep up to 64 requests in flight, after which its task reads no more until one completes. Senders end with their process.
- **Driver apps** (ROADMAP DA1). Node config `[drivers.<app>]` gives the app of that name, deployed and signed as any app, a profile its manifest cannot ask for: listening sockets the node binds and keeps (a driver's restart keeps the port), inherited at descriptors 8 to 13, on which its seccomp filter allows `accept4` and nothing else does (`accept`, `socket`, `connect` stay refused, and `accept4` on any other descriptor answers `EPERM`); files it may read, each a Landlock read rule on that file alone; and the apps it may send to, as its messaging ACL's `may_call`. Its calls are stamped with its own app name, so targets' `accept_from` applies to it too. The bytes of its connections never reach the node. On FreeBSD the listeners alone keep the `ACCEPT` right (with the stream rights below), and a driver reads its files through the `/driver` preopen's descriptor, as capability mode refuses paths. Under the helper a driver's files' directories are bound into its root read-only, and Landlock narrows them to the files.
- **FreeBSD** (ROADMAP FB1, FB2, 2026-11-12). The node, the channel, the rings, published snapshots, the lease watchdog and the parent-death signal work as on Linux, and the node and runner are not traceable (`procctl(PROC_TRACE_CTL)`, the runner's lasting across the exec into the app). The runner's fence is Capsicum: before the app's code runs it limits each inherited descriptor's rights (stdin read; stdout and stderr write; the channel's memfd read, write and map, without `FTRUNCATE`; the bell write; the door and the descriptor socket read; a driver's listeners accept and the stream rights), opens each preopen as a directory descriptor (lookup, read and map read-only; a read-write volume adds create, write, truncate, unlink, mkdir and rename), opens the run-time linker, the program and the library directories, enters capability mode and `fexecve`s the linker (`ld-elf.so.1 -f`, libraries through `LD_LIBRARY_PATH_FDS`). The app never runs outside capability mode, a hostile binary included: opening any path, `connect`, `bind` and signals to other processes are refused (`ECAPMODE`), and a right a descriptor lacks is refused (`ENOTCAPABLE`). The node passes later descriptors as duplicates limited the same way: a published snapshot read and map read-only, a connected stream read, write, poll, shutdown, socket names and options and the `FIONBIO` and `FIONREAD` ioctls (no `CONNECT`, `BIND`, `LISTEN` or `ACCEPT`), a sender channel's memfd, door and bell as the instance's own. `[native] landlock_optional` changes nothing there. A rustbridge plugin is refused, since loading it needs paths. Checked on the FreeBSD 15 VM (2026-11-12): the native, sockets, services, drivers, senders and listener suites and the native conformance suite; since ROADMAP FB3 (2026-11-16) the whole suite (`scripts/check.sh test`), which CI runs on FreeBSD 15 on every push, but for plugins and the node's `/proc` checks. Under the helper each instance also runs in a jail of its own (below). Without the helper there is no jail and no cgroup: both need root.
- **What an instance forked ends with it** (ROADMAP PS7). Under the helper, its cgroup's `cgroup.kill` (Linux) or its jail's removal (FreeBSD). Without it, the instance's own cgroup's `cgroup.kill` with `[native] cgroup`, else a `SIGKILL` to its process group, which it leads from its start: on a kill, and once more just after its own process ends, so a child left behind ends too (never again after that, as the group's id could then be reused). On Linux the seccomp filter refuses `setsid` and `setpgid`, so a child cannot leave the group. On FreeBSD without the helper capability mode allows `setsid`, and a child that calls it outlives the instance under the node's user; the helper's jail closes that (`tests/native_processes.rs` asserts both).
- **Gaps.** Native code is not memory-safe from the node's point of view: everything above is the boundary, not the language. The allow-list is one list for every app; a list per driver profile comes with driver apps (ROADMAP DA1), and the allowed calls' arguments are checked only as listed above. A TCP stream the node passed is the app's to read and write with its own system calls: the node counts it against `max_sockets` (or the listener's `max_connections`) and shuts it down when the app closes it or exits, but sees none of its bytes, and nothing limits their rate. A native singleton is killed at its lease's end by the runner's watchdog when the node cannot, within the watchdog's wake-up (its tests require the kill within 200 ms of the deadline, and pass on both machines, 2026-11-07); with `[native] landlock_optional` on a kernel without Landlock, the watchdog runs under seccomp alone. An executable that speaks the protocol without `bulkhead_native::app::serve` stays dumpable: its crashes go through the system's core handler, and the node's user can trace it as far as Yama allows (spike S30). The exec restriction is not a boundary of its own: since the ELF interpreter must be executable, a program can run any readable binary through it, but that binary inherits the same Landlock rules and seccomp filter. Without `[native] cgroup` or the helper there is no process limit, and memory is bounded only by `RLIMIT_DATA`; CPU is not limited with either (ROADMAP PS6b). Measured on the test VMs (2026-11-16) with an instance spinning at `cpu = 0.2`: 0.20 of a core on Linux, 0.27 to 0.33 over 8 s on FreeBSD, whose rctl throttles in bursts about once a second, starting from a whole core. A callback's deadline bounds a callback, but the program may run its own threads between callbacks. Landlock scopes (Linux 6.12) are not required: the seccomp filter covers signals, and refusing `socket` covers abstract Unix sockets; inherited descriptors are only stdin (empty), stdout and stderr (the node's log pipe), the channel's memfd, the bell's write end, the door's read end and its end of the descriptor socket, on which the node passes it descriptors and which the node's end never reads, so an app cannot pass descriptors to the node. A published bucket's snapshot goes only to instances whose manifest lists the bucket and whose grant includes it, as a memfd sealed against writes, shrinking and growing: an app reads what its grant lets it read, and cannot change what another app reads. The channel is memory the app shares with the node: the node reads the positions and frames the app writes there as it read the pipe's bytes, checking that a ring never holds more than its size, copying only inside its data area and decoding frames from its own copy, and ends an app that breaks the ring's rules. Each side spins for `[native] spin_us` (at most 10 ms) while waiting for the other, then sleeps, so a native app's traffic costs the node a worker's turns while it flows, and nothing while it stops. The program runs as the node's user: Landlock keeps it from that user's files, not from a kernel flaw an unprivileged process can reach. The seccomp filter refuses a short list, so the rest of the kernel's interface is reachable, where a component reaches only its imports. Tested on Linux 6.8 (Landlock ABI 4) on x86-64 and on a Raspberry Pi 5 with Linux 7.0 (aarch64), 2026-10-23, and with Phase 5's tests on both on 2026-11-01.

### The privileged helper

With node config `[priv]` (ROADMAP PS1), `bulkhead-priv` runs as root and the node as its own user; each app runs under a user of its own (OPERATIONS.md, "The privileged helper").

- **An app's user's files** (ROADMAP PS2). The node's files under `data_dir` are its own (umask 077, and tightened at each start): an app's user reads none of `kv/`, `bundles/`, `state.json` or another app's directories, on FreeBSD too, where capability mode refuses it every path. Its own program and `priv/` files are the node's with its group, given once by the helper when the node writes them; its read-write volumes are its own. Checked as root on Linux (Raspberry Pi 5, Ubuntu 26.04) and FreeBSD 15 (`tests/priv.rs`, the e2e scripts).
- **Controls.** The helper reads its checks from its own configuration (root's, writable by root only), never from the node: the one program an instance starts as (`bulkhead-runner`), the range of app users, the directories an instance's directories may be under, the ceilings on memory and processes, the low ports it binds. It picks each app's user itself and keeps the binding in its own state, so the node cannot run an app under another app's user (S36, finding 3). ZFS volumes (ROADMAP ZV1, spike S35): the node names an app and a volume, never a dataset; both are checked as names (lowercase letters, digits, `-`, `_`), the quota against the helper's `zfs_max_quota`, and the dataset is always `zfs_parent/APP/VOLUME`, made with `exec=off`, `setuid=off` and `devices=off` whatever the parent says. The helper runs the `zfs` command by its configured path with an empty environment; nothing else of the node's reaches its command line. A new volume's root is given to the app's user through a descriptor opened without following links, and only if it is root's; a volume is destroyed, or rolled back to its upgrade snapshot (ROADMAP ZV3), only while none of its app's instances runs; the snapshot's name is the helper's constant, `@upgrade`, never the node's. Requests are parsed by `bulkhead_priv_wire`, which forbids `unsafe`, bounds every string, list and message, and refuses trailing bytes; the fuzz target `priv_request` holds it. An instance's environment holds the runner's three variables only (no `LD_PRELOAD`), its descriptors only the numbers 1 to 15 the request names, with `/dev/null` as stdin and every other descriptor closed. Directories are shared with the app's group through descriptors opened without following links, changing only inodes the node's user already owns: whatever a compromised node points the helper at, it gives an app nothing the node could not give every user itself. A driver app's files (its certificates and keys, ROADMAP DA2) are shared one by one, read-only: a regular file the node's user owns and with one link gets the driver's group and `g+r`, and its directory, if the node's user owns it, search for others (`o+x`, no listing), since the directory is bound into the instance's root whole; other files there keep their own modes. A bind is checked in normal form, then again once links are resolved, and refused inside the system and kernel directories, or nested in another. The helper's `unsafe` code is one module of system calls (`sys`); the crate denies it elsewhere. Once the node runs, the helper sets `no_new_privs` and on Linux keeps nine capabilities, in every set and the bounding set, then installs a seccomp allow-list of its own (ROADMAP PS1b, 2026-11-16; `bulkhead_priv::seccomp`): a call off the list raises `SIGSYS`, and the helper writes `bulkhead-priv: system call N refused by the helper's seccomp filter` and exits with status 159, ending the node's connection and so every instance. A filter is inherited through `clone3` and `execve`, so every instance runs under it as well as the runner's own; the list is therefore the helper's calls, the runner's before its own filters (Landlock, `seccomp`) and every call the runner's filters allow or answer (a unit test keeps the runner's inside it). That is most of the ordinary interface; what it refuses is the rest, such as `open_by_handle_at` and `name_to_handle_at` (a way out of a mount namespace with the `CAP_DAC_READ_SEARCH` the helper keeps), `bpf`, kernel modules, `kexec`, the key calls, `perf_event_open`, `userfaultfd`, the new mount API, `setns`, `unshare`, `chroot`, swap, reboot, the clock setters, and calls a later kernel adds. An app meets the runner's answers unchanged, since both filters raise `SIGSYS` off their lists. Checked as root on the Ubuntu 26.04 VM (x86-64, Linux 7.0) and on the Raspberry Pi 5 (aarch64, Linux 7.0, glibc 2.43, 2026-11-19): `tests/priv.rs`, the conformance suite under the helper and `scripts/priv-e2e-systemd.sh`, each first with `BULKHEAD_PRIV_SECCOMP_LOG` (no call logged on either machine), then with the filter refusing. Linux instances get a cgroup, five namespaces and a minimal root; the node ends them through the cgroup's `cgroup.kill`, which ends what they forked too. The node itself holds no capabilities under the helper (it warns at start if it finds any): a TCP port below 1024 that the system refuses it, the helper binds and passes back (ROADMAP PS3b), only if its own configuration's `ports` lists the port, and only as a TCP listener; the node checks that what comes back is a listening TCP socket on the address it asked for. Checked as root on the Ubuntu 26.04 VM and the FreeBSD 15 VM (`tests/priv.rs`, the e2e scripts, which serve on port 80 and, on Linux, check the node's `CapEff` is zero).
- **Gaps.** The node is trusted with the code it deploys: it chooses what the runner executes, so a compromised node can run any code as any app's user, and so read that app's volumes. What the helper protects is root and the host from the node, and apps from each other. The helper's seccomp list is broad, since its instances inherit it, and checks no arguments: it keeps `mount`, `pivot_root`, the credential calls and `clone3` for itself. On FreeBSD the helper stays a full root process (it makes processes for other users, mounts and jails, which capability mode would refuse). On FreeBSD under the helper an instance is fenced by capability mode, its user, `RLIMIT_AS` and a jail of its own (ROADMAP FB2, 2026-11-12): a root the helper builds on a small tmpfs with read-only nullfs views of `/lib`, `/usr/lib`, `/libexec` and the runner's directory, the instance's directories at their own paths (read-write ones without `exec` or set-user-id), a devfs showing `null`, `zero`, `random`, `urandom` and `pvclock`, and a private `/tmp`; no IPv4 or IPv6; `rctl` rules on the jail (`vmemoryuse`, `memoryuse`, `maxproc`, `nthr`), so its processes share one budget; removed on a kill, which ends what the app forked. It sees no other app's directory names, and only its own jail's processes. `memoryuse` is enforced by paging out, not by refusing; `vmemoryuse`, the address space of all its processes, is the hard limit, a stricter count than Linux's resident `memory.max`. Checked as root on the FreeBSD 15 VM (`tests/priv.rs`, the conformance suite under the helper). Capability mode leaves `socket()` allowed, but such a socket can be neither bound nor connected. The lease watchdog, the runner's other half for a singleton, stays outside capability mode, which would refuse its kill of the app by pid; it keeps only the lease pipe and stderr, and the app, in capability mode, can neither signal nor trace it. On a KVM virtual machine libc cannot map `/dev/pvclock` in capability mode, so a clock read is a system call (about 160 ns against 50 on the FreeBSD VM, 2026-11-12). A bind is resolved before the fork and mounted after, so a compromised node that swaps a directory for a link in between shows the app what the link points at, under ordinary permissions. Files the node wrote into a read-write volume before the helper shared it stay the node's; volumes and `data_dir` get their per-app ownership with ROADMAP PS2. Under Landlock an instance's private `/tmp` is not writable.

### SQL datasources

Since ROADMAP DA3 (2026-11-15) each `[datasources.<name>]` has a driver of its own, `bulkhead-sql` running as the app `bulkhead-sql-<name>` (DESIGN.md, "SQL datasources"), so a Postgres reply is parsed by tokio-postgres in that process, and the node reads no datasource's password.

- **Credentials** come from a node secret (`password_secret`) and never reach an app; apps name datasources, not addresses. A secret's file is given to its datasource's driver alone, read-only under `/driver/` (shared with its user under the privileged helper, as certificates are), and the node does not open it; a secret from the node's environment is passed to the driver as its value, so that one the node does read.
- **Statements** are the app's own SQL, run with the datasource's user: what that user may do in the database is the operator's grant there. Parameters are bound, never interpolated. A statement timeout (server-side) and a result size cap bound each call; a connection cap per app and an acquire timeout bound what one app holds.
- **The node keeps the decisions.** It checks the grant and the datasource, holds the app's permit for each request and transaction, and keeps each instance's transactions by number, each pinned to the driver instance that began it; the driver is told no app identity and is trusted with none. A transaction still open when its instance exits is rolled back by a cast to the driver. A driver that restarted has lost its transactions, and their next statements answer `unavailable`, never another transaction's.
- **The driver's fence.** The runner's fence, as for any native instance, and under the helper a user of its own (a cgroup and namespaces, or a jail). Its profile is the node's: one connect endpoint, the datasource's address (TCP to its host, resolved by the node through the resolver driver on each new connection, or the Postgres socket in its Unix directory), which the node connects and passes as a descriptor, and its password and CA files read-only; no listening, binding or other files. Messages from its own instance alone (`messaging_acl`), so no app can call it; 256 MiB, one instance, a supervisor that never gives up. Peer authentication over the Unix socket sees the node's user, which connected.
- **Pooled connections are reset** with `ROLLBACK`, then `DISCARD ALL`, before reuse, so a transaction or session setting one call leaves does not reach the next caller, which may be another app. Each is sent alone: together in one message they failed every time (an implicit transaction block), and every connection was closed and replaced instead, from the start until 2026-11-15.
- **TLS** verifies the server against the CA file the operator names; there are no system roots. It runs in the driver, over the stream the node opened.
- **Tested** on Linux and FreeBSD 15, under the helper as root on both (`bulkhead-sql/tests`, `bulkhead-host/tests/sql.rs`, `native_sql.rs`, `priv.rs`, the e2e scripts, where strace shows the node making each connection and the driver none).
- **Gaps.** Apps that share a datasource share its database user and its driver, so the database cannot tell them apart; give each app its own datasource and user where that matters. A compromised driver holds its database's password and every result in clear, can run any statement that user may, and can answer an app's statement falsely; it reaches no other database, since the node connects it only to its own. A database server that can crash the driver (a bug in tokio-postgres) costs that datasource's open transactions and a second of restarts, not the node or another datasource.

### Modbus

Since ROADMAP DA5 (2026-11-15) Modbus is parsed in its drivers, never in the node (DESIGN.md, "Host services"): `bulkhead-modbus` (and, for `primary_only` devices, `bulkhead-modbus-primary`) for devices, `bulkhead-modbus-server` for masters.

- **Devices** are polled with a timeout per request; responses are parsed by tokio-modbus in the devices' driver, over connections the node opens to the configured addresses alone, so a compromised driver reaches the configured devices and nothing else.
- **The server** answers only masters in `server.allow` (loopback by default): Modbus has no authentication of its own. The node binds the port and passes it; the server's driver accepts on it alone and holds no device connection, so a master that compromises it reaches the served tables and the `deliver_to` app, not the devices.
- **Apps' calls** are checked by the node (the grant, the manifest's `read`, `write`, `serve`) before the driver sees them; the drivers accept messages from themselves alone, and their casts go to the `deliver_to` apps alone.
- **The drivers' fence.** The runner's, as for any native instance, and under the privileged helper a user of their own each (a cgroup and namespaces, or a jail); messages from themselves alone; no files. Tested on Linux and FreeBSD 15, under the helper as root on both (`bulkhead-modbus/tests`, `bulkhead-host/tests/drivers.rs`, `priv.rs`, `scripts/priv-e2e-systemd.sh`, where strace shows the node opening the device's connection and the driver none).
- **Gaps.** S4 is fixed. At most `server.max_connections` masters (default 32) are connected at once. A compromised devices' driver can write any register of the devices it polls, as a compromised node could before; a compromised server driver can answer masters falsely and cast false writes to its app.

### The metrics endpoint

- **Controls.** Off unless node config sets `[metrics] address`. Since ROADMAP DA7 served by the driver `bulkhead-metrics`, not the node: it answers `GET /metrics` only, read-only, with the text it asks the node for on each scrape (`Request::MetricsText`, the Prometheus text the admin API's `GET /v1/metrics` also gives), 64 connections at once, 10 s for a request's headers. It holds no file, key or call, in the runner's fence.
- **Gaps.** No authentication and no TLS: anyone who reaches the address reads every app's name, its instance counts, exit reasons, traffic and its own metrics' names and labels. Bind it to loopback or a management network.

### Liveness, membership and failover

- **Controls.** As for node and node; the failover rules R1 to R13 and their model (`docs/tla/VERIFICATION.md`). Serial heartbeat frames carry a CRC-16 and the sender's and receiver's node ids; frames that fail either check are dropped.
- **Serial line.** Frames on the pair's serial cable are not authenticated: whoever can reach the cable or a device on it can forge beats, which can keep a standby from promoting (a forged "primary alive") or renew a lease a primary would otherwise lose. The cable is treated as part of the pair's physical enclosure.
- **Gaps.** S5 is fixed. With a witness, an operator is asked to confirm a promotion only while the witness cannot be reached either, and a confirmation then is final: if the partner confirmed gone was alive, or restarts, and reaches the witness but not this node, both run until they hear each other (VERIFICATION.md, A9 and finding 6, accepted 2026-10-16); operators confirm only a partner that is down and stays down (powered off or fenced) until then. A primary paused past its lease no longer runs its singleton's callbacks when it continues (A8 in `docs/tla/VERIFICATION.md`).

### Replicated buckets

- **Controls.** Replication frames are taken only from the node's configured partner, over the cluster transport's mutual TLS, and are decoded by the replication module (CBOR) before anything is applied; an entry is applied only at the receiver's own epoch and after an entry that matches (spike S20's R6). Writes from the partner pass the same quota rules as local ones, with the quota the primary had. Linearizable reads are served only by a primary inside its lease.
- **Gaps.** The partner is trusted with the bucket's whole contents: a compromised partner can write, or snapshot over, every `cluster` bucket. A standby forwards any write a local app makes; the primary applies it without checking that the app is granted the bucket there (grants are per node, configured alike).

### Bundles, manifests and policy

- **Controls.** Signatures checked against operator keys only (never the key inside the bundle); checksums; manifest validation; the effective grant computed from the manifest and policy; `priv/` paths checked by Bulkhead on open and again on extraction (plain relative names only), as well as by rustbridge-bundle.
- **Gaps.** None found; S7 is fixed.
- **Programs** (`data_dir/compiled`) are the executables of deployed apps, written with mode 0500. Anyone who can write there as the node's user can run code as an app, as with the node's binary and configuration.

### Secrets and keys

- **Controls.** Secret values are read on each access and never printed: errors name the secret, and `Debug` shows only the source. Keys are written with mode 0600, and the cluster key and signer keys are refused on load if their group or others may access them, as ssh does. The node's process is not dumpable (Linux) unless node config sets `debuggable`, so other processes of its user cannot read its memory or environment, and it leaves no core.
- **Gaps.** None found; S9 is fixed. A test asserts that a secret's value appears in no log record, at any level or target, and in no error (`bulkhead-host` `tests/secrets.rs`).

The node holds every secret, the cluster key and all bucket data, so each row that stays is a way to all of them.

| Modbus: device replies and masters' requests | devices and masters | `tokio-modbus`, `bulkhead-modbus`, in the Modbus drivers since 2026-11-15; the server's requests fuzzed | moved (DA5): `scripts/check.sh deps` fails on tokio-modbus or `bulkhead-modbus` in the node's or the runtime's tree |
| Extensions' inputs | whatever the operator's code read | no longer: no code from outside Bulkhead runs in the node | removed (DA8, 2026-11-15): the `Extension` trait is gone; a service of an app's own is an app, fenced as any |
| The remote admin API: TLS handshakes and HTTP requests | anyone who reaches the address, before the operator's key is checked | rustls in the admin driver (`bulkhead-admin`) since 2026-11-14; the node's hyper reads what the driver carries, then checks each request's operator signature (`bulkhead_keys::signature`) | moved (DA7): `scripts/check.sh` fails on a TLS server for operators in the node's source and on the driver in its tree |
| The metrics endpoint: HTTP requests | anyone who reaches the address | hyper in the metrics driver (`bulkhead-metrics`) since 2026-11-14 | moved (DA7) |
| The admin Unix socket: HTTP requests and JSON | the operator | hyper, `serde_json` | yes: the operator is trusted with everything |
| Bundles | the operator who uploads one; the signer for what is inside | the zip container and the manifest are read by `rustbridge-bundle` before the signature is checked; the program and `priv/` files after it; fuzzed (`bundle_open`, `manifest`) | yes (DA6, 2026-11-14): a deploy is the operator's act. The zip reader runs on bytes no key has vouched for, which is accepted from an operator |
| The cluster transport before a peer is known: QUIC packets and the TLS 1.3 handshake | anyone who reaches the cluster address | quinn, rustls | yes, as an accepted risk: failover and replication need the transport in the node, and a driver between them would add a hand-off to every frame. Put the cluster address on a network of its own |
| The cluster transport after it: frames, heartbeats, replication entries | a cluster member | `transport::wire`, `failover::Status`, the replication module; fuzzed (`wire_packet`, `failover_status`, `dr_msg`). Shipping to a DR node (ROADMAP DR2): a pair node answers `Dr` frames from its `failover.dr` only, and the DR node reads them from its `dr.pair` only. Deployments shipped in them (DR3): the DR node checks every app name and version of a shipped state before any forms a path, fetches bundles by SHA-256 and verifies each with its own trusted keys, grants from its own policy, and takes no deploys of its own; a pair node serves only its kept bundles, by name and digest | yes: members are trusted |
| Serial heartbeat frames | whoever reaches the cable | `serial/frame.rs` (a CRC-16 and node ids) | yes: the cable is part of the pair's enclosure |
| App listeners and app sockets: accepts and UDP datagrams | any client | addresses only, from the kernel, checked against the rules; the bytes go to the app unparsed | yes (DA6, 2026-11-14): nothing is parsed, and a UDP socket cannot be passed to a process the node does not trust, since `sendmsg` can name any destination; the node checks each one |
| Host names: DNS replies | whoever answers DNS for a name: an app with a `connect` rule chooses the name for its sockets, an `[egress] allow` entry or a datasource's `host` for the others | hickory-resolver, in the resolver driver (`bulkhead-resolve`) since 2026-11-14; the node reads its answer, a list of addresses | moved (DA9): `scripts/check.sh` fails on libc's resolver in the node's source and on a DNS library in its tree |
| Node config, policy, peers and operators files | the operator | `toml`, the key parsers | yes |

## Findings

| # | Severity | Finding | Fix |
| --- | --- | --- | --- |
| S1 | medium, fixed 2026-10-10 | Two deployed apps could list the same registered name. The first instance to register it holds it; names are released when the holder exits, so each restart is a race the other app can win and receive the messages meant for the first. | Fixed: a deploy, upgrade or rollback that lists a name another deployed app lists, running or stopped, is refused (`conflict`). |
| S2 | medium, fixed 2026-10-10 | App log messages and contexts were written as given. A newline starts what looks like a new host record, with any timestamp and target: checked with tracing-subscriber 0.3.23, which escapes ANSI sequences but not newlines. Operators' logs, and the soak's checker, which reads the gate's records, can be fooled. | Fixed: control characters in app text (log messages and contexts, stdout and stderr lines, crash reasons) are escaped. |
| S3 | medium, fixed 2026-10-10 | App stdout and stderr became log records with no rate limit, and an app's own `rate_limit_per_sec` was optional, so one app could flood the node's log. | Fixed: every app has a budget, the node's `[limits] log_records_per_sec` (default 1000) or its own lower rate, shared by its log records and its stdout and stderr lines. |
| S4 | medium, fixed 2026-10-10 | The Modbus server accepted reads and writes from any master that reached its address; a write changes the served table and is cast to the `deliver_to` app. | Fixed: `server.allow` lists the masters' addresses or networks, loopback only by default; MANIFEST.md says to bind it to the SCADA interface. `server.max_connections` (default 32) caps the masters connected at once (2026-10-11). |
| S5 | low, fixed 2026-10-10 | A pair node took failover answers (`Granted`, `LeaseOk`, `Fenced`, `NotYet`, `Refused`) from any member, not only its witness: a faulty member's `Granted` promotes the standby. | Fixed: answers from any node but the configured witness are dropped and logged. |
| S6 | low, fixed 2026-10-10 | A volume's `quota` was accepted but not enforced (documented): an app with a writable volume can fill the disk. | Fixed: a manifest `quota` on a directory volume is refused, since nothing enforces one; MANIFEST.md tells operators to give each writable directory a filesystem quota. Since ROADMAP ZV1 (2026-11-22) a ZFS volume takes the manifest's `quota`, enforced by ZFS. |
| S7 | low, fixed 2026-10-10 | `priv/` extraction relied on rustbridge-bundle for path safety. | Fixed: Bulkhead refuses a bundle with a `priv/` path that is not plain relative names (`..`, `.`, a root, an empty part, `:` or a backslash), on open and again on extraction. |
| S8 | low, fixed 2026-10-10 | Each incoming `Frame::Call` started a task with no bound; an honest peer is bounded by its instances' `pending_calls_max`, a faulty one was not. | Fixed: at most `[cluster] incoming_calls_max` (default 10,000) calls from one peer run at once; beyond it a call is answered `overloaded`, with one warning until the peer is back to half the limit. |
| S9 | low, fixed 2026-10-10 | The cluster key and signer keys were loaded without checking their permissions. | Fixed: a key its group or others may access is refused, with a message to `chmod 600` it. |
| S10 | medium, fixed 2026-11-08 | A native app whose manifest declared `bulkhead:files` kept its volumes and `priv/` files when the operator's policy denied the capability: the node did not check the grant. | Fixed: the node passes a native app its preopens only with the grant (`native/port.rs`); `tests/services.rs` and the node's `tests/node.rs` hold it. |
| S11 | high, fixed 2026-11-11 | The memfd holding a native instance's rings was made without seals. The app holds it read-write (an app that does not use `bulkhead_native::app::serve`, or keeps a copy before it, has the descriptor), and neither the seccomp filter nor Landlock refuses `ftruncate` on an inherited descriptor. Truncated, the node's next read of the ring faulted with `SIGBUS`: one app ended the node and every app on it. Found in a review of the code against the goals; reproduced with the native fixture. | Fixed: `Channel::create` seals the memfd's size (`F_SEAL_SHRINK`, `F_SEAL_GROW`, `F_SEAL_SEAL`; writes stay open, since both sides write). `bulkhead-native`'s `create____memfd_resized____refused` and `bulkhead-host`'s `executable____shrinks_its_channel____refused_and_the_node_runs_on` hold it. |

## Fuzz targets

In `fuzz/`, run nightly for five minutes each: `bundle_open`, `manifest`, `parse` (the small parsers: pids, sizes, routing, port ranges, CIDRs, capability keys, package names), `routing_key`, `process_ops`, and these, by who controls the input:

| Target | Input from | Function |
| --- | --- | --- |
| `wire_packet` | cluster members | `transport::wire::decode` and the hello's version agreement |
| `failover_status` | the partner | `failover::Status::decode` (heartbeat payloads) |
| `http_reply` | apps | the ingress driver's reading of a reply: `bulkhead_sdk::http::Response::from_reply` and `bulkhead-ingress`'s `serve::response` |
| `state_view` | apps | `node/state_view.rs`, which decodes an app's snapshot for `bulkhead state` |
| `modbus_request` | Modbus masters | the server's request handling against its tables (address and count bounds) |
| `native_frame` | native apps | `bulkhead_native::hot::parse_from_app` (hot frames) and the CBOR frame decoder the port uses |
| `ring_reader` | native apps, through the shared memory | `bulkhead_native::channel::Ring::read` against positions and data the app stores at will, then `bulkhead-host`'s frame splitter (`native/link.rs`, `next_frame`) over what it read (ROADMAP T1b). Its first run found the reader's `head + n` overflowing when the app stored a position near `u64::MAX` (a panic with overflow checks; wrapping now, 2026-11-16) |
| `priv_request` | the node, read by the root helper | `bulkhead_priv_wire::Request::decode` and `Reply::decode`: no panic, and what decodes encodes back to the same bytes |

Private functions are exported for fuzzing the way `routing_key` is: `#[cfg(fuzzing)] #[doc(hidden)]`.

## Not reviewed

Dependencies beyond `cargo deny` (advisories, licences, sources); denial of service by a cluster member, which the trust model above accepts; the SDK as an attack surface for apps themselves.
